2. PURPOSE & VALUE

What problem does this data product solve? What decision, analysis, or use case does it support?

This data product solves the challenge of working with raw, unclean financial transaction data by providing a curated, analytics-ready dataset. It eliminates the need for users to handle data quality issues like duplicates, missing keys, and inconsistent timestamps. The product supports daily transaction monitoring, channel performance analysis, counterparty risk assessment, and merchant category analysis. By providing pre-aggregated gold tables, it enables rapid insights without requiring users to write complex ETL logic or deal with data quality remediation.

4. HOW TO ACCESS THIS PRODUCT

    Where is the product published? PostgreSQL Database (Docker container)

    Direct link: https://github.com/username/BGD (Git Repository)

    How to download or query it:
        1. Start PostgreSQL: docker compose up -d
        2. Run pipeline: uv run python -m src.main
        3. Connect: psql -h localhost -p 5432 -U user -d bigdata
        4. Query: SELECT * FROM silver LIMIT 10;

    Credentials or access notes: Credentials stored in .env file (see .env.example)

    Example file/table name: silver, gold_daily, gold_by_channel, gold_by_type, gold_top_counterparties, gold_by_mcc, gold_channel_share

9. EXAMPLE USAGE

Business question:

What are the daily transaction trends over the past week?

Example query / code / steps:

SELECT
    day,
    txn_count,
    total_amount,
    avg_amount
FROM gold_daily
ORDER BY day DESC
LIMIT 7;



Or using Python:

import pandas as pd
import psycopg2

conn = psycopg2.connect(
    host="localhost", port=5432,
    database="bigdata", user="user", password="pass"
)
df = pd.read_sql("SELECT * FROM gold_by_channel", conn)
print(df)



10. LIMITATIONS & RISKS

    - Data is static (no real-time updates from source systems)

    - Source data quality depends on Kaggle dataset accuracy

    - Timestamp parsing may fail for non-standard formats

    - Counterparty and MCC data may have gaps or null values

    - No historical versioning - tables are rebuilt on each pipeline run

    - UNLOGGED tables (Bronze, Silver) - data lost on PostgreSQL restart

    - Gold tables limited to top 20 counterparties and MCC codes
